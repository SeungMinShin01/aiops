# AIOps MVP 기능 요구사항 (v0.1 ~ v0.3)

- 문서 버전: 1.0 (2026-10-28) · 상태: 확정 (D-079)
- 범위: v0.1 에러 수집 + v0.2 멀티테넌시 + v0.3 웹 콘솔 = **MVP**
- 근거 문서: `aiops-v0.1-architecture.md`, `v0.2-multitenancy.md`, `v0.3-web-console.md`
- 담당: `mvp-worklist.md`의 단계별 담당표를 따른다 (단계 담당제, D-079)
- 쓰는 법: 요구사항 하나가 배분 단위다. `선행`이 끝나야 시작할 수 있고, `⚠`는 틀리면 팀 앱이 망가지거나 다른 팀 데이터가 새는 항목이라 핵심 로직 후보다.

---

## 0. MVP가 끝나면 되는 것 (한 문장)

관리자가 기수와 팀을 만들면 디스코드 채널이 자동으로 생기고, 조장은 초대 링크로 들어와 키를 받고, 팀원은 의존성과 키만 넣으면 런타임 에러가 AI 설명과 함께 자기 팀 디스코드 채널로 오며, 웹 콘솔에서 **자기 팀 것만** 볼 수 있다.

**MVP 밖:** 성능 지표(v0.4), Redis 큐·VM 분리(v0.5), 배포 감지·다운 감지(v0.6), 부하 테스트(v0.7), 리포트(v1.0), GitHub App(v1.1) 이후 전부

## 1. 사용자

| 사용자 | 하는 일 |
|---|---|
| 팀 앱 (Starter) | 팀원 PC·서버에서 에러를 모아 보냄 |
| 팀원 | 디스코드 알림 확인, 콘솔에서 자기 팀 에러 확인 |
| 조장 | 팀원 권한 + 키 발급·폐기, 팀원 초대 |
| 관리자 (우리) | 기수·팀 생성, 조장 초대, 정지, 전체 현황, Grafana |

## 3. 비기능 요구사항

| ID | 요구사항 | 확인 방법 |
|---|---|---|
| N1 | 우리 서버가 죽어도 팀 앱은 정상 | 안전성 테스트 1 |
| N2 | 팀 앱 요청을 느리게 하지 않음 | 안전성 테스트 1 (응답 지연 없음) |
| N3 | 키가 없으면 경고만 남기고 꺼짐 | 안전성 테스트 2 |
| N4 | 메모리를 무한히 쓰지 않음 | 안전성 테스트 4 (에러 1,000개 연속) |
| N5 | 설정 값·요청 본문·헤더 수집 안 함, 민감정보 가림 | 안전성 테스트 5, S-11 테스트 |
| N6 | 팀 프로젝트에 새 라이브러리 최소 (Spring·Logback·Jackson은 `compileOnly`) | 의존성 트리 확인 |
| N7 | 팀 미설정 시 DB 결과 0건 (fail closed) | 격리 테스트 (T-06) |
| N8 | 키 원문·봇 토큰·웹훅 주소·OAuth 비밀값은 로그·응답·프롬프트에 없음 | 코드 리뷰 + 로그 검색 |
| N9 | 권한 판단은 백엔드에서만 | 권한 E2E |
| N10 | LLM 호출 일일 상한 | 상한 초과 시 설명 없이 알림 |

**Starter 안전성 테스트 5종** (S 담당자가 작성): ① 서버가 꺼져도 앱 정상·지연 없음 ② 키 없으면 꺼짐 ③ 시작 실패가 서버에 도착 ④ 에러 1,000개에도 메모리 그대로 ⑤ 민감정보가 가려져 도착

## 4. MVP 완료 시나리오 (전체 통합 테스트)

1. 관리자가 기수 1개 + 팀 2개를 만든다 → 팀마다 디스코드 역할·채널 2개·웹훅이 생긴다
2. 조장이 초대 링크 → GitHub 로그인 → 키 발급 화면에서 local 키를 받는다
3. 팀원이 초대 링크로 합류 → [디스코드 연결] → 자기 팀 채널만 보인다
4. 샘플 앱에 키를 넣고 실행 → 콘솔에 "연결됨"
5. `/boom/npe` 호출 → #local 채널에 AI 설명 알림 → 콘솔 목록·상세에 표시
6. 같은 에러 10번 → 그룹 1개·횟수 10, 알림 1번
7. DB를 끄고 샘플 앱 실행 → STARTUP 에러 도착
8. 다른 팀 번호로 URL 변경 → 403, DB 직접 조회도 0건
9. 우리 서버를 꺼도 샘플 앱은 정상 응답
10. 키 폐기 → 그 키로 보낸 요청 401
